Module 1: What is Jupyter Notebook?

Before you teach a tool, you need to truly understand it. This module traces Jupyter from its origins to its current status as the gold standard in interactive computing.

  • Define Jupyter Notebook and its purpose
  • Understand the origin story and the meaning behind the name
  • Distinguish Jupyter from a regular Python script or IDE
  • Recognize the file format (.ipynb) and what it contains

🌱 The Origin Story

Imagine you're a scientist in 2014, juggling Python scripts, output files, and a separate Word document where you paste your findings. Every time you change a parameter, you re-run the script, dig through the terminal output, update the Word doc, and hope you haven't lost track of which analysis corresponds to which results. This was the daily frustration that drove Fernando Pérez — a physicist at UC Berkeley — to create what would become Jupyter Notebook.

Jupyter grew out of an earlier project called IPython (Interactive Python), launched in 2001. IPython was initially just a better Python shell: it had syntax highlighting, tab completion, and a history feature. But as Pérez and his collaborators began building more sophisticated scientific workflows, they realized the command-line model was fundamentally limiting. Scientists needed a way to weave together executable code, rich documentation, mathematical equations, and visualizations — all in one document that someone else could actually read and reproduce.

The Jupyter name itself is a tribute to three core scientific programming languages: Julia, Python, and R. It signals from the start that Jupyter was designed to be language-agnostic. While Python remains by far the most popular language used with Jupyter, the notebook architecture supports dozens of "kernels" — the engine that runs the code — allowing instructors and researchers to work in Scala, Ruby, JavaScript, C++, and many others.

📄 So What Exactly Is It?

At its core, Jupyter Notebook is a web-based interactive computing environment. When you open Jupyter, you're running a local web server on your own machine. Your browser becomes the interface, but everything executes locally — no internet connection required for the code itself. This distinction matters when you're in a cybersecurity lab environment and need to analyze network traffic or run scripts on sensitive data without it leaving your network.

A Jupyter Notebook is a single document — saved with the .ipynb extension — that contains an ordered list of cells. Each cell can hold one of three things: executable code (like Python), formatted text written in Markdown, or raw data. When you run a code cell, the output appears directly below it in the same document. This means your analysis and its results always travel together, making notebooks exceptionally reproducible.

Under the hood, an .ipynb file is simply a JSON document. Open one in a text editor and you'll find metadata about the kernel, plus an array of cell objects, each with a type, source content, and stored outputs. This transparency is actually useful — it means version control systems like Git can diff notebook files, and notebooks can be exported to HTML, PDF, or Python script formats with a single command.

💡 Faculty Tip: When you share a notebook with students, they receive both the code and the explanation together. There's no "lost context" because everything is embedded. This makes Jupyter ideal for lab handouts, demonstrations, and graded assignments alike.

🔄 Jupyter vs. A Regular Script

You might reasonably ask: "I already know Python — why not just write a .py file?" It's a fair question. The answer is about workflow, not capability. A Python script runs top to bottom, all at once. If you want to inspect the state of a variable halfway through, you add a print statement, re-run the whole script, and scan the output. This is fine for production software, but frustrating for exploratory analysis — especially when you're working with large packet capture files or network logs where one full run might take thirty seconds.

With Jupyter, you can run individual cells independently. You can run a cell that loads a 500MB packet capture file, confirm it loaded correctly, and then write and test your analysis code in subsequent cells without ever re-loading that file. Each cell maintains the state of the previous cells in the same session. This interactivity is Jupyter's killer feature for education: students can pause, experiment, make mistakes, fix them, and continue — all without starting over.

🏭 Industry Adoption: Why It Matters to Your Students

Before we talk about pedagogy, let's be honest about workforce reality. Your students will graduate and seek jobs in security operations centers, network engineering teams, and threat intelligence units. They will encounter Jupyter Notebooks — possibly on their first day. Security researchers at companies like CrowdStrike, Palo Alto Networks, and Microsoft publish threat analysis notebooks on GitHub. CISA has published notebooks for analyzing indicators of compromise. Jupyter is the lingua franca of applied data analysis in the security space.

According to the Stack Overflow Developer Survey, Python has been among the most-used programming languages for years running, and Jupyter is Python's most popular interactive environment in academic and research contexts. The SANS Institute regularly features Jupyter-based workshops for security practitioners. If a student doesn't know how to open and run a Jupyter notebook, they're arriving at the job with a gap — and you can close that gap with a single well-designed lab assignment.

🎯 Real-World Signal: The Elastic Security Lab, Microsoft Threat Intelligence, and MITRE ATT&CK projects all distribute Jupyter notebooks for threat hunting, log analysis, and detection engineering. These aren't niche tools — they're industry standard artifacts.

📚 Pedagogical Benefits for Faculty

Even if you're not primarily a data science instructor, Jupyter offers specific advantages that translate directly to how you already teach networking and security topics.

  • 🔬
    Live Demonstrations: Show a port scan or packet analysis live, with code students can modify and re-run. No more "take my word for it."
  • 📖
    Lab Handouts That Run: Instead of a PDF lab guide, give students a notebook where the instructions and the code are the same document.
  • 🐛
    Visible Error Handling: Students see real error messages in context, developing debugging instincts alongside technical skills.
  • 📊
    Inline Visualization: Graph a network's traffic anomalies right next to the code that generates it — no switching between apps.
  • ♻️
    Reproducibility: Students can share notebooks that actually reproduce their results — building the documentation habits employers want.
  • 🤝
    Scaffolding Made Easy: Pre-fill some cells, leave others blank — Jupyter supports "fill in the blank" style assignments naturally.

🤔 Addressing Common Faculty Concerns

When introducing new tools to a curriculum, legitimate concerns arise. Let's address the most common ones directly, because your hesitation is probably shared by the faculty member in the next office.

Concern 1: "My students don't have Python backgrounds."
Response: Jupyter actually lowers the barrier to entry for Python. Because students can run one cell at a time and see immediate results, they build confidence faster than in a script-based environment. You can scaffold cells so early exercises require almost no original code — students modify, not write from scratch.
Concern 2: "Installation will take half a class period."
Response: Not necessarily. Anaconda distribution installs Jupyter in one step. JupyterHub can be deployed institution-wide so students access notebooks through a browser with no local install. Google Colab offers free Jupyter-compatible notebooks in the cloud — no installation at all.
Concern 3: "What about academic integrity — students can just share notebooks."
Response: This is true of any file-based assignment, but Jupyter actually makes individualized outputs easier to require. Ask students to run cells with their name embedded, include narrative reflection in Markdown cells, or use unique datasets. The reasoning a student writes in Markdown is much harder to copy meaningfully than code alone.
Concern 4: "Is this really relevant to networking, not just data science?"
Response: Absolutely relevant. Jupyter notebooks are used for parsing PCAP files with Scapy, analyzing firewall logs with Pandas, running Nmap scans via Python wrappers, building network traffic visualizations, and conducting forensic analysis. We cover exactly these use cases in Module 5.

📄 Notebook Filename (.ipynb)

The title bar shows the active notebook filename, always ending in .ipynb. This is a JSON file containing all your cells, outputs, and kernel metadata. You can rename it by clicking the title. The name is important for organization — especially when students submit assignments — so teach naming conventions from day one (e.g., lastname_lab03.ipynb).

🛠️ The Toolbar

The toolbar provides quick access to the most common actions: adding new cells (Code or Markdown), running the current cell (▶), stopping a running cell (⏹), and restarting the kernel (⟳). The Kernel status indicator in the top-right corner tells you whether the kernel is idle (○) or busy (●). A busy kernel means code is executing — students sometimes think their notebook froze when it's actually processing a large dataset.

📝 Markdown Cells

Markdown cells render rich-formatted text: headings, bold, italics, bullet lists, links, images, and even LaTeX math. In a cybersecurity context, these cells are where students document their analysis: "I ran an Nmap scan on subnet 10.0.0.0/24 at 14:32 and found 12 hosts with port 22 open." This narrative context transforms a code file into an investigative report. Teaching students to use Markdown cells builds technical writing skills alongside coding skills.

⚙️ Code Cells + Output

Code cells contain executable code. The In [2]: label shows execution order — the number increments each time a cell runs. If you see In [*]:, the cell is currently running. Below the code is the output area, which displays whatever the code produces: text, tables, charts, error messages. The output is stored in the notebook file itself, so when you share a completed notebook, others see the outputs without needing to re-run anything.

🧠 Kernel Session

The empty cell with a cursor (In [ ]:) is waiting to be run. It has no output yet because it hasn't been executed. The kernel — the Python engine running in the background — maintains all variables defined in previously-run cells. If you restart the kernel, all variables reset to zero, even if the cell outputs are still visible. This is a common source of confusion for students: they see output from a previous run but the variable is no longer in memory. Always "Restart & Run All" before submitting.

🛠️ Installation: Three Paths

There are three primary ways to get Jupyter running, each suited to different classroom contexts. Choose the one that fits your environment — you don't have to commit to just one approach. Many faculty use Anaconda for their own machines and recommend Colab for student access.

Path 1 — Anaconda Distribution (Recommended for Local Install): Anaconda is a free distribution that bundles Python, Jupyter, and over 150 data science libraries in a single installer. It's the simplest route. Download from anaconda.com/download, run the installer, and Jupyter is ready. On Windows, you'll find "Jupyter Notebook" in the Start menu. On macOS/Linux, open a terminal and type:

Terminal
# After installing Anaconda: jupyter notebook

Path 2 — pip (If Python Is Already Installed): If your students already have Python, pip installation is a one-liner:

Terminal
# Install Jupyter via pip pip install notebook # Launch it jupyter notebook

Path 3 — JupyterHub (Institution-Wide, No Student Install): JupyterHub runs on a server and serves each student their own Jupyter environment in a browser. Students log in, no installation needed. This is the cleanest solution for a managed classroom, and many community colleges partner with cloud providers to offer this at minimal cost. If your institution uses Canvas, students can even authenticate through their existing school login.

☁️ Cloud Alternative: Google Colab

Google Colaboratory (Colab) is a free, cloud-hosted Jupyter environment. Students sign in with a Google account, and notebooks are stored in Google Drive. There is no installation, no IT support ticket, and no "it works on my machine" debugging. Colab uses a nearly identical interface to Jupyter, with a few minor UI differences and the addition of runtime options (including free GPU access).

For security faculty, Colab has one important caveat: you should not upload sensitive data — like real packet captures from your network — to a Google-hosted environment. For those exercises, local Jupyter or a campus JupyterHub is more appropriate. But for introductory labs using public datasets (CVE databases, publicly available log samples, synthetic network data), Colab is an excellent frictionless starting point.

💡 Faculty Workflow Tip: Create your course notebooks in Colab during curriculum development — the autosave, version history, and comment features are excellent for solo work. Then distribute them to students via JupyterHub or Canvas if your institution has those resources.

🕵️ Use Case 1: Network Traffic Analysis

One of the most compelling Jupyter applications in cybersecurity is analyzing network captures — the kind students create in Wireshark labs. Instead of just reading a Wireshark GUI, students can load a PCAP file with the Scapy library and programmatically interrogate every packet. This teaches both Python and network protocol knowledge simultaneously.

Consider a typical scenario: a student captures 10 minutes of traffic on the campus network (with proper authorization). In Jupyter, they load the capture, filter for DNS requests, group by source IP, and plot the top 10 most active hosts. In thirty lines of code and five Markdown cells, they've produced a report that would take hours to generate manually in Wireshark.

Python — Scapy PCAP Analysis Starter
# Lab 4: Analyzing network traffic with Scapy # Required: pip install scapy pandas matplotlib from scapy.all import rdpcap, DNS, IP import pandas as pd import matplotlib.pyplot as plt # Load the packet capture packets = rdpcap('lab_capture.pcap') # Extract DNS queries dns_queries = [] for pkt in packets: if pkt.haslayer(DNS) and pkt[DNS].qr == 0: dns_queries.append({ 'src_ip': pkt[IP].src, 'query': pkt[DNS].qd.qname.decode() }) df = pd.DataFrame(dns_queries) # Output: DataFrame with columns src_ip, query # Students can then: df['src_ip'].value_counts().plot(kind='bar')

🔐 Use Case 2: Log Analysis and SIEM Simulation

Security analysts spend a significant portion of their time sifting through logs. Jupyter is an ideal environment for teaching this skill because students can interact with real log data step by step, making decisions at each stage rather than running a black-box script. This mirrors how analysts work in tools like Splunk or Microsoft Sentinel — but with full transparency of what's happening under the hood.

A practical exercise: give students a CSV export of Apache access logs from a simulated web server. Ask them to identify all 404 error requests, group them by user agent, and flag any user agents that appear more than 50 times in an hour — a simple but effective heuristic for directory brute-forcing.

Python — Web Server Log Analysis
import pandas as pd from datetime import datetime # Load Apache access log (pre-parsed to CSV) logs = pd.read_csv('access_log.csv', parse_dates=['timestamp']) # Filter 404 errors errors = logs[logs['status'] == 404] # Count requests per user_agent per hour errors['hour'] = errors['timestamp'].dt.floor('H') suspicious = (errors.groupby(['user_agent', 'hour']) .size() .reset_index(name='count')) # Flag agents with more than 50 requests/hour flagged = suspicious[suspicious['count'] > 50] # Output: DataFrame of suspicious user agents and their request volumes

🗺️ Use Case 3: IP Geolocation and Threat Visualization

Students are highly engaged when they can visualize threat data on a map. Jupyter notebooks integrate beautifully with geolocation APIs (like ip-api.com or MaxMind) and mapping libraries like Folium. A lab exercise might ask students to take a list of suspicious IP addresses from a firewall log and produce an interactive world map showing where connection attempts originated — a task that illustrates both geolocation concepts and the global nature of cybersecurity threats.

This type of exercise connects naturally to discussions of attribution, geoblocking policies, and the limitations of IP-based threat intelligence. The notebook becomes a conversation starter, not just a coding exercise.

🔍 Use Case 4: Vulnerability Data Analysis (CVE/NVD)

The National Vulnerability Database (NVD) provides machine-readable CVE data via a free API. Students can use Jupyter to query recent CVEs, filter by CVSS score, group by vendor, and visualize trends over time. This exercise teaches API consumption (an essential modern skill), JSON parsing, and data visualization — all in the context of a dataset students care about because it represents real-world threats to systems they'll be defending.

🎯 Assignment Idea: "Pull the last 30 days of Critical CVEs from the NVD API. Which vendor had the most critical vulnerabilities? Plot severity distribution over time. In your Markdown cells, explain what this means for a security operations team's patching priority queue."
