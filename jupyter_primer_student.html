What Is Jupyter Notebook?

You've probably seen security researchers share their work in "notebooks." This is what those are — and why they matter.

What .ipynb files are Code + docs in one place Why analysts use it

Before anything else, watch this short video. It'll give you a visual feel for what Jupyter looks like running — way easier than trying to imagine it from text alone.

Video 1 — What is Jupyter Notebook? Watch before reading on.

📓 The Short Version

Jupyter Notebook is a tool that lets you write code and see the results right below the code, in the same page. You can also add written explanations around your code — formatted text, headings, bullet lists — so your work tells a story, not just runs a script.

The files it creates end in .ipynb. That stands for "IPython Notebook," which is what it was called before it became Jupyter. When you open one of these files, you see a document made of cells. Some cells contain code. Some contain text (written in Markdown). When you run a code cell, the output appears directly beneath it.

Key Concept A Jupyter notebook is like a lab report that runs itself. The code, the output, and your written explanation all live in the same document.

The name "Jupyter" is a mashup of three languages: Julia, Python, and R. That tells you something important: Jupyter was always designed to work with more than just Python. But Python is by far the most common language used with it — especially in cybersecurity.

🆚 Notebook vs. Script — What's the Difference?

You might already know how to write a Python script — a .py file that runs from top to bottom. A Jupyter notebook is different in a key way: you run it one chunk at a time. You can write ten lines, run them, check the output, fix something, and continue — without re-running everything from the beginning.

For security work, this is huge. Imagine loading a 400MB packet capture file. With a script, any change requires re-running the entire thing — loading that giant file all over again. With Jupyter, you load the file once in one cell, and then write and test your analysis code in separate cells below. Much faster.

✅ Use a Notebook When... You're exploring data, running a security lab, building an analysis report, or showing your work step by step.
⚙️ Use a Script When... You've finished your analysis and need to automate it — running the same steps every day on fresh data, for example.

🌐 Where Do Analysts Actually Use This?

Jupyter notebooks aren't just a classroom tool. Security teams at companies like Microsoft, CrowdStrike, and Palo Alto Networks publish threat analysis notebooks on GitHub. The MITRE ATT&CK project distributes notebooks for threat hunting. CISA has released notebooks for analyzing malware indicators. When you learn Jupyter now, you're learning a real professional tool — not a toy.

🔎 Try This Right Now Google "site:github.com jupyter notebook cybersecurity threat hunting" — you'll find dozens of real-world security analysis notebooks written by working analysts. Bookmark one that looks interesting.

Component Details

📄 The Filename (.ipynb)

The notebook is saved as packet_analysis.ipynb. Every Jupyter file uses this extension. It's actually a JSON file containing all your cells, their outputs, and metadata about the Python version used. When your instructor says "submit your notebook," this is the file they want. Rename it before submitting — good habit: lastname_lab03.ipynb.
🛠️ The Toolbar

From left to right: add a code cell, add a text (Markdown) cell, run the selected cell, stop a running cell, restart the Python kernel. The kernel status in the top-right corner is critical — a filled circle (●) means Python is busy running something. If it's been spinning for more than a minute, something may be stuck.
📝 Markdown (Text) Cells

Markdown cells let you write formatted text — headings with #, bold with **text**, bullet lists with - . When you run a Markdown cell, it renders into formatted text. Use these to explain what your code is doing and what the results mean. In a real security lab report, your Markdown cells are where you document your analysis findings.
⚙️ Code Cell + Output

The In [1]: means this was the 1st cell executed this session. The code runs and its output appears directly below in the same cell. That output is saved in the notebook file — so when you share your notebook, the recipient sees your results even without re-running anything. Green text = output from the code.
🧠 Empty Cell + Kernel Memory

This cell hasn't run yet — that's why the bracket is empty [ ]. But here's the important part: the kernel (the Python engine running in the background) already knows everything from the cells above. So if you defined a variable in cell 1, you can use it in cell 5 without redefining it. If the kernel restarts, that memory clears — you'd need to re-run the earlier cells.

⌨️ Shortcuts You Need to Know

Two modes exist in Jupyter: Edit Mode (green/blue cell border, you're typing inside a cell) and Command Mode (blue border, you're controlling cells, not editing them). Press Escape to enter Command Mode; press Enter to go back to Edit Mode.

ShortcutWhat It DoesMode

⚠️ Common Mistake New students often press D in Command Mode and accidentally delete a cell. If that happens, immediately press Ctrl+Z (Cmd+Z on Mac) — Jupyter has undo. Also: don't confuse "kernel restart" with closing your browser. Closing the tab doesn't stop the kernel — you need to explicitly shut it down from the dashboard.

📡 Use Case 1: Analyzing Network Traffic

In a network security course, you'll capture traffic with Wireshark. But what if you want to programmatically sift through thousands of packets and count how many came from each IP address? That's a job for Python + Jupyter. The library is called Scapy, and it lets you load a .pcap file and examine every single packet in Python.

Python — Your First Packet Analysis
# Scapy lets you work with real network packets in Python # Install it: pip install scapy from scapy.all import rdpcap, IP # Load a packet capture file (your Wireshark lab output) packets = rdpcap('lab_capture.pcap') # Count packets per source IP ip_count = {} for pkt in packets: if pkt.haslayer(IP): src = pkt[IP].src ip_count[src] = ip_count.get(src, 0) + 1 # Show the top talkers sorted_ips = sorted(ip_count.items(), key=lambda x: x[1], reverse=True) for ip, count in sorted_ips[:5]: print(f"{ip}: {count} packets") # Output: # 192.168.1.105: 2847 packets ← possible scanner? # 10.0.0.1: 1203 packets # 8.8.8.8: 891 packets
Why This Matters An IP sending 2,847 packets when most are sending under 100 is suspicious. This kind of outlier detection is exactly what security analysts do — and Jupyter makes it easy to visualize alongside the code.

📋 Use Case 2: Parsing Firewall / Web Server Logs

Security analysts spend a huge portion of their time reading logs. Instead of manually scrolling through thousands of lines, you can load a log file into a Jupyter notebook with Pandas — Python's data analysis library — and ask specific questions: "Show me all 404 errors. Which IP addresses triggered the most of them?"

Python — Finding Suspicious Activity in Logs
import pandas as pd # Load an Apache web server access log (exported as CSV) logs = pd.read_csv('web_access_log.csv') # Filter for 404 Not Found errors (common in web scanners/brute force) errors_404 = logs[logs['status'] == 404] # Which IPs hit the most 404s? (could be directory scanning) top_offenders = (errors_404['client_ip'] .value_counts() .head(10)) print(top_offenders) # Output: # 203.0.113.42 847 # 198.51.100.7 312 # 10.0.0.99 89 # An IP with 847 404s in one session = likely a scanner
