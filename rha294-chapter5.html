File Modules Overview

Ansible provides multiple modules for managing files on managed hosts. Choosing the right module depends on your specific task.

Commonly Used File Modules

The ansible.builtinThe core collection of Ansible modules that comes bundled with ansible-core. These modules are always available without additional installation. collection provides several modules for file management:

Module Description
blockinfile Insert, update, or remove a block of multiline text surrounded by customizable marker lines
copy Copy a file from the control node to managed hosts with optional content generation
fetch Retrieve files from managed hosts to the control node, organized by hostname
file Set attributes like permissions, ownership, SELinux contexts; create/remove files, directories, symlinks
lineinfile Ensure a particular line is in a file, or replace an existing line using regex
stat Retrieve status information for a file, similar to the Linux stat command
template Process Jinja2 templates and deploy resulting files to managed hosts

Additional Useful Modules

The ansible.posixA collection of modules for POSIX-compliant systems. Included in the default automation execution environment. collection provides additional file management modules:

Module Description
synchronize Wrapper around rsync for efficient file synchronization between hosts
patch Apply patch files to modify files
File Deployment Flow
Control Node
Source files & templates
↓
ansible.builtin.template / copy
Process and transfer
↓
Managed Hosts
Deployed configuration files
💡 Best Practice

Always use the Fully Qualified Collection Name (FQCN)The complete module name including the collection namespace, such as ansible.builtin.copy instead of just copy. This avoids naming conflicts and improves clarity. when writing playbooks, such as ansible.builtin.copy instead of just copy.

Copy and Fetch Modules

Transfer files between the control node and managed hosts in both directions.

The ansible.builtin.copy Module

The copy moduleCopies files from the control node to managed hosts. Can also generate file content directly using the content parameter. copies files from the Ansible working directory on the control node to managed hosts.

Basic copy example 
- name: Copy configuration file to managed hosts
  ansible.builtin.copy:
    src: files/httpd.conf
    dest: /etc/httpd/conf/httpd.conf
    owner: root
    group: root
    mode: '0644'

Key Parameters

Parameter Description
src Path to source file on control node (relative to playbook or files/ directory)
dest Absolute path on the managed host where file will be placed
content Write content directly to dest instead of copying a file
owner User that will own the file
group Group that will own the file
mode Permissions mode (use quoted string like '0644')
force Replace file if contents differ (default: true)
backup Create backup before overwriting (default: false)

Using the content Parameter

Generate file content directly without a source file:

Creating content directly 
- name: Create index.html with dynamic content
  ansible.builtin.copy:
    content: |
      <h1>Welcome to {{ ansible_hostname }}</h1>
      <p>Server IP: {{ ansible_default_ipv4.address }}</p>
    dest: /var/www/html/index.html
    mode: '0644'

The ansible.builtin.fetch Module

The fetch moduleThe opposite of copy - retrieves files from managed hosts and stores them on the control node, organized in a directory tree by hostname. retrieves files from managed hosts and stores them on the control node:

Fetching SSH keys from managed hosts 
- name: Retrieve SSH public key from reference host
  ansible.builtin.fetch:
    src: "/home/{{ user }}/.ssh/id_rsa.pub"
    dest: "files/keys/{{ user }}.pub"
    flat: true
⚠️ Important: flat Parameter

By default, fetch creates a directory structure: dest/hostname/path/to/file. Set flat: true to store directly in the dest path without the hostname subdirectory.

The File Module

Manage file and directory attributes, create structures, and set permissions on managed hosts.

ansible.builtin.file

The file moduleSets attributes such as permissions, ownership, SELinux contexts, and timestamps. Can also create or remove files, symlinks, hard links, and directories. is versatile for managing file attributes and states.

Creating Directories

Create a directory structure 
- name: Ensure application directory exists
  ansible.builtin.file:
    path: /opt/myapp/config
    state: directory
    owner: appuser
    group: appgroup
    mode: '0755'

State Values

State Description
file Set attributes on existing file (default if path exists)
directory Create directory if missing; set attributes
link Create symbolic link
hard Create hard link
touch Create empty file if missing; update timestamp
absent Delete file or directory recursively

Creating Symbolic Links

Create a symlink 
- name: Create symbolic link to current version
  ansible.builtin.file:
    src: /opt/myapp/releases/v2.1.0
    dest: /opt/myapp/current
    state: link

Removing Files and Directories

Remove a file or directory 
- name: Remove old configuration
  ansible.builtin.file:
    path: /etc/myapp/old.conf
    state: absent
🔥 Caution

Using state: absent on a directory will recursively delete all contents. Double-check your paths before running!

Lineinfile & Blockinfile

Modify specific lines or blocks within existing files without replacing the entire content.

ansible.builtin.lineinfile

The lineinfile moduleEnsures a particular line is present in a file, or replaces an existing line matching a regular expression. Useful for single-line configuration changes. manages single lines in text files:

Ensure a line exists in a file 
- name: Ensure SELINUX is set to enforcing
  ansible.builtin.lineinfile:
    path: /etc/selinux/config
    regexp: '^SELINUX='
    line: 'SELINUX=enforcing'

Key Parameters

Parameter Description
path The file to modify
line The line to insert or ensure is present
regexp Regex to find existing line to replace
state present (default) or absent
insertafter Insert after matching line or EOF
insertbefore Insert before matching line or BOF
backup Create backup before modifying

Adding Lines at Specific Positions

Insert line after another 
- name: Add proxy configuration after [main]
  ansible.builtin.lineinfile:
    path: /etc/yum.conf
    insertafter: '^\\[main\\]'
    line: 'proxy=http://proxy.example.com:8080'

ansible.builtin.blockinfile

The blockinfile moduleInserts, updates, or removes a block of multiline text surrounded by customizable marker lines. The markers help identify and manage the block. manages blocks of text with marker lines:

Add a block of text to a file 
- name: Add custom SSH configuration block
  ansible.builtin.blockinfile:
    path: /etc/ssh/sshd_config
    block: |
      # Custom settings for application servers
      Match Group appusers
        X11Forwarding no
        AllowTcpForwarding no
    marker: "# {mark} ANSIBLE MANAGED BLOCK - APP SERVERS"
💡 Marker Lines

The marker parameter uses {mark} as a placeholder that gets replaced with BEGIN and END. Default markers are # BEGIN ANSIBLE MANAGED BLOCK and # END ANSIBLE MANAGED BLOCK.

When to Use Each Module

📝
lineinfile
Single configuration values, key=value pairs, one-line settings
📋
blockinfile
Multiple related lines, configuration sections, script snippets

Synchronize Module

Efficiently synchronize directory trees using rsync for large file transfers.

ansible.posix.synchronize

The synchronize moduleA wrapper around the rsync command that efficiently synchronizes files and directories. Much faster than copy for large directory trees since it only transfers differences. uses rsync to efficiently transfer files and directories:

Synchronize a directory to managed hosts 
- name: Sync application files
  ansible.posix.synchronize:
    src: ./webapp/
    dest: /var/www/html/
    delete: true
    recursive: true

Key Parameters

Parameter Description
src Source path (trailing slash means contents only)
dest Destination path on managed host
mode push (default), pull, or delegate
delete Delete files in dest that don't exist in src
recursive Recurse into directories
rsync_opts Additional rsync options as a list
⚠️ Trailing Slash Matters

A trailing slash on src means "copy the contents of this directory". Without it, the directory itself is copied. src: ./webapp/ creates files in dest, while src: ./webapp creates dest/webapp/.

Pulling Files from Remote

Pull files from managed host to control node 
- name: Backup remote logs
  ansible.posix.synchronize:
    src: /var/log/myapp/
    dest: ./backups/{{ inventory_hostname }}/
    mode: pull

Template Basics

Create dynamic configuration files that adapt to each managed host using Jinja2 templates.

Why Use Templates?

Templates allow you to create configuration files that include host-specific values, calculated settings, and conditional content. Instead of maintaining separate config files for each server, you maintain one template.

🎯
Dynamic Content
Insert hostnames, IP addresses, memory sizes, and other facts automatically.
🔄
Single Source
Maintain one template file instead of multiple static configurations.
🧮
Calculated Values
Compute settings based on available resources like memory or CPU count.

The ansible.builtin.template Module

The template moduleProcesses Jinja2 template files on the control node and deploys the rendered output to managed hosts. Similar to copy but with variable substitution. processes Jinja2 templates and deploys the results:

Deploy a template 
- name: Deploy Apache configuration from template
  ansible.builtin.template:
    src: templates/httpd.conf.j2
    dest: /etc/httpd/conf/httpd.conf
    owner: root
    group: root
    mode: '0644'
    validate: '/usr/sbin/httpd -t -f %s'
  notify: Restart httpd
💡 File Naming Convention

Template files conventionally use the .j2 extension (e.g., httpd.conf.j2) to indicate they are Jinja2 templates. Store them in a templates/ directory relative to your playbook.

Template Directory Structure

Recommended project layout 
project/
├── ansible.cfg
├── inventory
├── playbook.yml
├── files/
│   └── static-file.txt
└── templates/
    ├── httpd.conf.j2
    └── my.cnf.j2

The validate Parameter

Use validate to check configuration syntax before finalizing the file. The %s placeholder represents the temporary file path:

Common validation commands 
# Apache configuration
validate: '/usr/sbin/httpd -t -f %s'

# Nginx configuration
validate: '/usr/sbin/nginx -t -c %s'

# sudoers file
validate: '/usr/sbin/visudo -cf %s'

Jinja2 Syntax

Learn the delimiters and syntax for expressions, statements, and comments in Jinja2 templates.

Jinja2 Delimiters

Jinja2A modern templating engine for Python. Ansible uses Jinja2 for variable substitution in playbooks and for processing template files. uses specific delimiters to distinguish template code from literal text:

Delimiter Purpose Example
{{ }} Output expressions (variables, calculations) {{ ansible_hostname }}
{% %} Statements (control structures) {% if condition %}
{# #} Comments (not included in output) {# This is a comment #}

Variable Substitution

Insert variable values using double curly braces:

templates/motd.j2 
{# Message of the Day template #}
===============================================
Welcome to {{ ansible_hostname }}

System Information:
  OS: {{ ansible_distribution }} {{ ansible_distribution_version }}
  Kernel: {{ ansible_kernel }}
  Memory: {{ ansible_memtotal_mb }} MB
  IP Address: {{ ansible_default_ipv4.address }}

Managed by Ansible - Do not edit manually!
===============================================

Accessing Nested Data

Access dictionary keys and list items using dot notation or bracket notation:

Nested variable access 
{# Dot notation #}
{{ ansible_default_ipv4.address }}
{{ server_config.database.host }}

{# Bracket notation (required for keys with special characters) #}
{{ ansible_facts['default_ipv4']['address'] }}
{{ users['john.doe'].email }}

{# List access by index #}
{{ dns_servers[0] }}

Control Structures

Use loops and conditionals in templates to generate dynamic content based on data.

Using Loops

The for statementIterates over a sequence (list, dictionary, or string). Each iteration makes the current item available in the loop body. iterates over sequences to generate repeated content:

templates/hosts.j2 - Iterating over a list 
{# Generate /etc/hosts entries #}
127.0.0.1   localhost localhost.localdomain
::1         localhost localhost.localdomain

{% for host in groups['webservers'] %}
{{ hostvars[host].ansible_default_ipv4.address }}   {{ host }}
{% endfor %}

Loop Variables

Jinja2 provides special variables inside loops:

Variable Description
loop.index Current iteration (1-indexed)
loop.index0 Current iteration (0-indexed)
loop.first True if first iteration
loop.last True if last iteration
loop.length Total number of items
Using loop variables 
{% for user in users if user != 'root' %}
User {{ loop.index }} of {{ loop.length }}: {{ user }}
{% endfor %}

Using Conditionals

The if statementEvaluates a condition and includes content only if the condition is true. Can include elif and else branches. includes content conditionally:

templates/httpd.conf.j2 - Conditional content 
ServerName {{ ansible_fqdn }}

{% if ansible_memtotal_mb > 2048 %}
MaxRequestWorkers 400
{% else %}
MaxRequestWorkers 150
{% endif %}

{% if enable_ssl is defined and enable_ssl %}
LoadModule ssl_module modules/mod_ssl.so
SSLEngine on
SSLCertificateFile /etc/pki/tls/certs/server.crt
SSLCertificateKeyFile /etc/pki/tls/private/server.key
{% endif %}

Combining Loops and Conditionals

templates/vhosts.conf.j2 
{% for vhost in virtual_hosts %}
<VirtualHost *:{{ vhost.port | default(80) }}>
    ServerName {{ vhost.name }}
    DocumentRoot {{ vhost.docroot }}
{% if vhost.aliases is defined %}
{% for alias in vhost.aliases %}
    ServerAlias {{ alias }}
{% endfor %}
{% endif %}
</VirtualHost>

{% endfor %}
💡 Whitespace Control

Use {%- and -%} to strip whitespace around control statements. This prevents unwanted blank lines in output.

Jinja2 Filters

Transform and format data using built-in and Ansible-specific filters.

What are Filters?

FiltersFunctions that transform data. Applied using the pipe character (|) after a variable. Multiple filters can be chained together. modify variable output using the pipe syntax:

Basic filter syntax 
{{ variable | filter_name }}
{{ variable | filter_name(argument) }}
{{ variable | filter1 | filter2 | filter3 }}

Common Filters

FilterDescriptionExample
upper Convert to uppercase {{ name | upper }} → JOHN
lower Convert to lowercase {{ name | lower }} → john
capitalize Capitalize first letter {{ name | capitalize }} → John
replace Replace substring {{ path | replace('/', '-') }}
regex_replace Regex replacement {{ str | regex_replace('^prefix_', '') }}
FilterDescriptionExample
to_json Convert to JSON string {{ data | to_json }}
to_yaml Convert to YAML string {{ data | to_yaml }}
to_nice_json Pretty-printed JSON {{ data | to_nice_json }}
from_json Parse JSON string {{ json_str | from_json }}
from_yaml Parse YAML string {{ yaml_str | from_yaml }}
FilterDescriptionExample
default Use value if undefined {{ port | default(80) }}
mandatory Fail if undefined {{ api_key | mandatory }}
default(omit) Omit parameter if undefined owner: {{ owner | default(omit) }}
FilterDescriptionExample
int Convert to integer {{ '42' | int }}
float Convert to float {{ '3.14' | float }}
round Round number {{ 3.7 | round }} → 4
abs Absolute value {{ -5 | abs }} → 5

Practical Examples

templates/my.cnf.j2 - Calculated memory values 
[mysqld]
{# Calculate innodb_buffer_pool_size as 70% of total memory #}
innodb_buffer_pool_size = {{ (ansible_memtotal_mb * 0.7) | int }}M

{# Use default if variable not defined #}
max_connections = {{ mysql_max_connections | default(151) }}

{# Join list items with commas #}
bind-address = {{ mysql_bind_addresses | default(['127.0.0.1']) | join(',') }}

Guided Exercise

Practice deploying files and templates to managed hosts.

Exercise: Deploy Web Server Configuration
Estimated time: 30 minutes
1

Create project structure

Set up your working directory with the proper structure:

mkdir -p ~/deploy-files/{files,templates}
cd ~/deploy-files
2

Create the template file

Create templates/httpd.conf.j2:

{# Apache configuration template #}
ServerRoot "/etc/httpd"
Listen {{ http_port | default(80) }}

ServerAdmin {{ server_admin | default('root@localhost') }}
ServerName {{ ansible_fqdn }}:{{ http_port | default(80) }}

DocumentRoot "/var/www/html"

{% if ansible_memtotal_mb > 2048 %}
# High memory configuration
MaxRequestWorkers 400
ServerLimit 400
{% else %}
# Standard memory configuration
MaxRequestWorkers 150
ServerLimit 150
{% endif %}
3

Create the playbook

Create deploy-webserver.yml:

---
- name: Deploy web server configuration
  hosts: webservers
  become: true
  vars:
    http_port: 80
    server_admin: "admin@example.com"

  tasks:
    - name: Ensure httpd is installed
      ansible.builtin.dnf:
        name: httpd
        state: present

    - name: Deploy httpd.conf from template
      ansible.builtin.template:
        src: templates/httpd.conf.j2
        dest: /etc/httpd/conf/httpd.conf
        owner: root
        group: root
        mode: '0644'
      notify: Restart httpd

    - name: Ensure httpd is started
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true

  handlers:
    - name: Restart httpd
      ansible.builtin.service:
        name: httpd
        state: restarted
4

Run the playbook

Execute and verify:

ansible-playbook deploy-webserver.yml

# Verify the deployment
ansible webservers -m command -a "head -20 /etc/httpd/conf/httpd.conf"

Objectives

In this lab, you will:
