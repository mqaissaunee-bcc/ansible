📅 Week 1

Managing Software and Subscriptions

Use Ansible to manage software packages, configure repositories, and handle Red Hat subscriptions across your infrastructure.

Managing Packages with DNF

The ansible.builtin.dnfThe package manager module for RHEL 8+, Fedora, and CentOS Stream. It manages software packages using DNF. module manages packages on systems that use the DNF package manager (RHEL 8+, Fedora, CentOS Stream):

Installing packages with DNF 
- name: Install multiple packages
  ansible.builtin.dnf:
    name:
      - httpd
      - php
      - mariadb-server
    state: present

- name: Install the latest version
  ansible.builtin.dnf:
    name: httpd
    state: latest

- name: Install a package group
  ansible.builtin.dnf:
    name: "@Development Tools"
    state: present

- name: Remove a package
  ansible.builtin.dnf:
    name: telnet
    state: absent

Package State Options

State Description
present Ensure package is installed (default version)
latest Ensure the latest version is installed (updates if needed)
absent Ensure the package is removed
installed Alias for present
removed Alias for absent

The YUM Module for Legacy Systems

For RHEL 7 and earlier systems, use the ansible.builtin.yumThe package manager module for RHEL 7 and earlier systems that use the YUM package manager. module:

Using the YUM module 
- name: Install package with yum
  ansible.builtin.yum:
    name: httpd
    state: present

- name: Update all packages
  ansible.builtin.yum:
    name: "*"
    state: latest
💡 Best Practice

Use the ansible.builtin.package module when writing playbooks that need to work across different Linux distributions. It automatically uses the correct package manager for each system.

Configuring YUM Repositories

The ansible.builtin.yum_repositoryA module that creates and manages YUM repository configuration files in /etc/yum.repos.d/. module manages repository configuration files:

Adding a custom repository 
- name: Add EPEL repository
  ansible.builtin.yum_repository:
    name: epel
    description: "Extra Packages for Enterprise Linux"
    baseurl: "https://dl.fedoraproject.org/pub/epel/$releasever/$basearch/"
    gpgcheck: true
    gpgkey: "https://dl.fedoraproject.org/pub/epel/RPM-GPG-KEY-EPEL-$releasever"
    enabled: true

- name: Disable a repository
  ansible.builtin.yum_repository:
    name: epel
    enabled: false

Managing Red Hat Subscriptions

The community.general.redhat_subscriptionA module for managing Red Hat subscriptions, allowing systems to register with the customer portal or Satellite server. module automates subscription management:

Registering with Red Hat 
- name: Register system with Red Hat
  community.general.redhat_subscription:
    state: present
    username: "{{ rhn_username }}"
    password: "{{ rhn_password }}"
    auto_attach: true

- name: Register with activation key
  community.general.redhat_subscription:
    state: present
    org_id: "{{ org_id }}"
    activationkey: "{{ activation_key }}"

- name: Unregister system
  community.general.redhat_subscription:
    state: absent
⚠️ Security Warning

Never store Red Hat credentials in plain text. Use Ansible Vault to encrypt sensitive variables like usernames, passwords, and activation keys.

Enabling and Disabling Repositories

Use the community.general.rhsm_repositoryA module for enabling or disabling Red Hat Subscription Manager repositories on registered systems. module to manage which repositories are enabled:

Managing RHSM repositories 
- name: Enable specific repositories
  community.general.rhsm_repository:
    name:
      - rhel-9-for-x86_64-baseos-rpms
      - rhel-9-for-x86_64-appstream-rpms
    state: enabled

- name: Disable all repos and enable only specific ones
  community.general.rhsm_repository:
    name: "*"
    state: disabled

- name: Enable required repositories
  community.general.rhsm_repository:
    name: rhel-9-for-x86_64-baseos-rpms
    state: enabled

Managing Users and Authentication

Ansible provides powerful modules for managing user accounts, groups, SSH keys, and authentication across your infrastructure.

The User Module

The ansible.builtin.userA core Ansible module for managing user accounts on Unix-like systems, including creating, modifying, and deleting users. module manages user accounts:

Creating and managing users 
- name: Create a user with specific attributes
  ansible.builtin.user:
    name: devuser
    uid: 2001
    group: developers
    groups: wheel,docker
    shell: /bin/bash
    home: /home/devuser
    create_home: true
    comment: "Development User Account"
    state: present

- name: Create user with encrypted password
  ansible.builtin.user:
    name: secureuser
    password: "{{ 'MyPassword123' | password_hash('sha512') }}"
    update_password: on_create

- name: Remove a user and their home directory
  ansible.builtin.user:
    name: olduser
    state: absent
    remove: true

Important User Module Parameters

Parameter Description
name Username (required)
uid User ID number
group Primary group
groups Supplementary groups (comma-separated)
append If true, adds to groups instead of replacing
password Encrypted password hash
update_password When to update: always, on_create
generate_ssh_key Generate SSH key pair for user

The Group Module

The ansible.builtin.groupA module for managing groups on Unix-like systems, including creating, modifying, and deleting groups. module manages groups:

Managing groups 
- name: Create a group
  ansible.builtin.group:
    name: developers
    gid: 3000
    state: present

- name: Create system group
  ansible.builtin.group:
    name: appservice
    system: true
    state: present

- name: Remove a group
  ansible.builtin.group:
    name: obsolete
    state: absent

Managing SSH Authorized Keys

The ansible.posix.authorized_keyA module for managing SSH authorized keys, allowing you to add or remove public keys from user accounts. module deploys SSH public keys:

Deploying SSH keys 
- name: Add authorized key from file
  ansible.posix.authorized_key:
    user: devuser
    key: "{{ lookup('file', '/home/admin/.ssh/id_rsa.pub') }}"
    state: present

- name: Add authorized key with options
  ansible.posix.authorized_key:
    user: devuser
    key: "ssh-rsa AAAAB3NzaC1yc2E..."
    key_options: 'no-port-forwarding,from="10.0.0.0/8"'
    state: present

- name: Ensure only specified keys are present
  ansible.posix.authorized_key:
    user: devuser
    key: "{{ lookup('file', 'authorized_keys') }}"
    exclusive: true

Configuring Sudo Access

Use the ansible.builtin.copy or ansible.builtin.template module to manage sudoers files:

Configuring sudo access 
- name: Allow developers sudo without password
  ansible.builtin.copy:
    dest: /etc/sudoers.d/developers
    content: "%developers ALL=(ALL) NOPASSWD: ALL\n"
    owner: root
    group: root
    mode: '0440'
    validate: '/usr/sbin/visudo -cf %s'

- name: Deploy sudoers template
  ansible.builtin.template:
    src: sudoers.j2
    dest: /etc/sudoers.d/custom
    owner: root
    group: root
    mode: '0440'
    validate: '/usr/sbin/visudo -cf %s'
💡 Best Practice

Always use the validate parameter when modifying sudoers files. This runs visudo to check syntax before saving, preventing lockouts from syntax errors.

Managing the Boot Process and Scheduled Processes

Use Ansible to manage system services, configure boot targets, and schedule tasks using cron and at.

Managing Services with systemd

The ansible.builtin.serviceA generic module that manages services across different init systems including systemd, SysV init, and others. module manages services across different init systems:

Managing services 
- name: Start and enable httpd
  ansible.builtin.service:
    name: httpd
    state: started
    enabled: true

- name: Stop and disable a service
  ansible.builtin.service:
    name: firewalld
    state: stopped
    enabled: false

- name: Restart service
  ansible.builtin.service:
    name: httpd
    state: restarted

- name: Reload service configuration
  ansible.builtin.service:
    name: httpd
    state: reloaded

Service States

State Description
started Ensure service is running
stopped Ensure service is not running
restarted Stop then start the service
reloaded Reload configuration without stopping

The systemd Module

The ansible.builtin.systemdA module specifically for managing systemd services with additional features like daemon_reload and scope settings. module provides systemd-specific features:

Using the systemd module 
- name: Start service after deploying unit file
  ansible.builtin.systemd:
    name: myapp
    state: started
    enabled: true
    daemon_reload: true

- name: Reload systemd daemon
  ansible.builtin.systemd:
    daemon_reload: true

- name: Manage user service
  ansible.builtin.systemd:
    name: podman
    scope: user
    state: started

Using Handlers for Service Restarts

Handlers are a best practice for restarting services only when configurations change:

Using handlers efficiently 
tasks:
  - name: Deploy configuration file
    ansible.builtin.template:
      src: httpd.conf.j2
      dest: /etc/httpd/conf/httpd.conf
    notify: restart apache

handlers:
  - name: restart apache
    ansible.builtin.service:
      name: httpd
      state: restarted

Scheduling Tasks with Cron

The ansible.builtin.cronA module for managing crontab entries, allowing you to create, modify, or remove scheduled tasks. module manages cron jobs:

Creating cron jobs 
- name: Schedule daily backup at 2 AM
  ansible.builtin.cron:
    name: "Daily backup"
    minute: "0"
    hour: "2"
    job: "/usr/local/bin/backup.sh"
    user: root

- name: Run at system reboot
  ansible.builtin.cron:
    name: "Startup script"
    special_time: reboot
    job: "/usr/local/bin/startup.sh"

- name: Every 15 minutes
  ansible.builtin.cron:
    name: "Health check"
    minute: "*/15"
    job: "/usr/local/bin/health.sh"

- name: Remove a cron job
  ansible.builtin.cron:
    name: "Old task"
    state: absent

Cron Time Specifications

Parameter Values Description
minute 0-59, *, */n Minute of hour
hour 0-23, *, */n Hour of day
day 1-31, *, */n Day of month
month 1-12, *, */n Month of year
weekday 0-6 (Sun-Sat) Day of week
special_time reboot, hourly, daily, weekly, monthly, annually Shortcuts

One-time Tasks with At

The ansible.posix.atA module for scheduling one-time tasks using the at daemon. module schedules one-time tasks:

Scheduling one-time tasks 
- name: Schedule maintenance in 2 hours
  ansible.posix.at:
    command: "/usr/local/bin/maintenance.sh"
    count: 2
    units: hours
    unique: true

- name: Schedule task for specific time
  ansible.posix.at:
    command: "/usr/local/bin/report.sh"
    count: 30
    units: minutes
💡 Best Practice

Use the unique: true parameter with the at module to prevent duplicate jobs from being scheduled if the playbook is run multiple times.

Managing Storage

Configure storage including partitions, LVM, and file systems using Ansible and RHEL System Roles.

The Storage System Role

The redhat.rhel_system_roles.storageA Red Hat certified system role for comprehensive storage management including partitions, LVM, and file systems. role provides comprehensive storage management. This role simplifies complex storage tasks by handling partitions, volume groups, logical volumes, and file systems.

📦 Installing the Storage Role

Install the RHEL System Roles package on your control node:

sudo dnf install rhel-system-roles
Configuring LVM storage 
- name: Configure storage with RHEL System Role
  hosts: servers
  become: true
  
  vars:
    storage_pools:
      - name: data_vg
        type: lvm
        disks:
          - /dev/sdb
          - /dev/sdc
        volumes:
          - name: data_lv
            size: "10 GiB"
            fs_type: xfs
            mount_point: /data
          - name: backup_lv
            size: "5 GiB"
            fs_type: ext4
            mount_point: /backup
  
  roles:
    - redhat.rhel_system_roles.storage

Storage Role Variables

Variable Description
storage_pools List of storage pool definitions (VGs)
name Name of the volume group
type Storage type: lvm, partition, disk
disks List of block devices for the pool
volumes List of logical volumes to create
size Size with unit (GiB, MiB, etc.)
fs_type File system type: xfs, ext4, swap
mount_point Where to mount the volume

Creating Partition-based Storage

For simpler storage needs, create partition-based file systems:

Partition-based storage 
storage_volumes:
  - name: data
    type: partition
    disks:
      - /dev/sdb
    size: "10 GiB"
    fs_type: xfs
    mount_point: /data
    mount_options: defaults,noatime

Managing Mounts and File Systems

For direct control without the system role, use individual modules:

Using individual modules 
- name: Create a file system
  community.general.filesystem:
    fstype: xfs
    dev: /dev/sdb1

- name: Mount and add to fstab
  ansible.posix.mount:
    path: /data
    src: /dev/sdb1
    fstype: xfs
    opts: defaults,noatime
    state: mounted
💡 Best Practice

Use the storage system role when possible. It handles the complexity of storage configuration and ensures idempotent, declarative management of your storage infrastructure.

Managing Network Configuration

Configure network interfaces, static IP addresses, and firewall rules using Ansible.

The Network System Role

The redhat.rhel_system_roles.networkA RHEL System Role for configuring network connections, interfaces, and related settings consistently across systems. role provides comprehensive network configuration management:

Configuring static IP address 
- name: Configure network with RHEL System Role
  hosts: servers
  become: true
  
  vars:
    network_connections:
      - name: eth0
        type: ethernet
        interface_name: eth0
        autoconnect: true
        state: up
        ip:
          address:
            - 192.168.1.100/24
          gateway4: 192.168.1.1
          dns:
            - 192.168.1.1
            - 8.8.8.8
  
  roles:
    - redhat.rhel_system_roles.network

Network Role Connection Types

Type Description
ethernet Standard wired network interface
bond Bonded interface for redundancy
bridge Software bridge for VMs
vlan VLAN-tagged interface
team Team interface (alternative to bonding)

Configuring DHCP

Configure an interface for DHCP:

DHCP configuration 
network_connections:
  - name: eth0
    type: ethernet
    interface_name: eth0
    autoconnect: true
    state: up
    ip:
      dhcp4: true

Managing Firewall Rules

The ansible.posix.firewalldA module for managing firewalld rules, allowing you to open ports, add services, and configure zones. module manages firewall rules:

Configuring firewall rules 
- name: Ensure firewalld is running
  ansible.builtin.service:
    name: firewalld
    state: started
    enabled: true

- name: Allow HTTP service
  ansible.posix.firewalld:
    service: http
    permanent: true
    immediate: true
    state: enabled

- name: Allow HTTPS service
  ansible.posix.firewalld:
    service: https
    permanent: true
    immediate: true
    state: enabled

- name: Open custom port
  ansible.posix.firewalld:
    port: 8080/tcp
    permanent: true
    immediate: true
    state: enabled

- name: Configure rich rule for specific source
  ansible.posix.firewalld:
    rich_rule: 'rule family="ipv4" source address="10.0.0.0/8" service name="ssh" accept'
    permanent: true
    immediate: true
    state: enabled

Firewalld Module Parameters

Parameter Description
service Predefined service name (http, ssh, etc.)
port Port/protocol (8080/tcp, 53/udp)
zone Firewall zone (public, trusted, etc.)
permanent Save to persistent configuration
immediate Apply to runtime configuration
rich_rule Complex firewall rule
📌 Important

Always set both permanent: true and immediate: true when configuring firewall rules. This ensures rules persist across reboots and apply immediately.

Using the Firewall System Role

For complex firewall configurations, use the redhat.rhel_system_roles.firewall role:

Using the firewall system role 
- name: Configure firewall with system role
  hosts: servers
  become: true
  
  vars:
    firewall:
      - service:
          - http
          - https
        state: enabled
      - port:
          - "8080/tcp"
          - "8443/tcp"
        state: enabled
  
  roles:
    - redhat.rhel_system_roles.firewall
