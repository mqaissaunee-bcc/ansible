Managing Users and Groups

Ansible provides powerful modules for managing user accounts and groups across your infrastructure.

The User Module

The ansible.builtin.userA core Ansible module for managing user accounts on Unix-like systems. It can create, modify, or remove users. module manages user accounts on managed hosts.

Creating a user account
- name: Create developer user
  ansible.builtin.user:
    name: devuser
    comment: "Developer Account"
    uid: 1050
    group: developers
    groups: wheel,docker
    shell: /bin/bash
    create_home: true
    state: present

Key User Module Parameters

ParameterDescription
nameUsername to create, modify, or remove (required)
uidNumeric user ID
groupPrimary group for the user
groupsSupplementary groups (comma-separated)
appendAdd to groups without removing from others
shellUser's login shell
passwordEncrypted password (use password_hash filter)
statepresent or absent

The Group Module

The ansible.builtin.groupA module for managing groups on Unix-like systems. Create groups before users that depend on them. module manages group accounts.

Managing groups
- name: Create developers group
  ansible.builtin.group:
    name: developers
    gid: 1050
    state: present

Setting Passwords Securely

Use the password_hashA Jinja2 filter that generates a password hash. Supports sha256, sha512, and other algorithms. filter to hash passwords:

Setting user password
- name: Create user with password
  ansible.builtin.user:
    name: newuser
    password: "{{ 'mypassword' | password_hash('sha512') }}"
    update_password: on_create
⚠️ Security Warning

Never store plaintext passwords. Use Ansible Vault to encrypt sensitive variables.

Bulk User Management

Creating multiple users with loop
- name: Create developer accounts
  ansible.builtin.user:
    name: "{{ item.name }}"
    uid: "{{ item.uid }}"
    groups: "{{ item.groups }}"
    state: present
  loop:
    - name: alice
      uid: 2001
      groups: developers
    - name: bob
      uid: 2002
      groups: developers,wheel
  loop_control:
    label: "{{ item.name }}"

SSH Keys and Sudo Access

Secure your infrastructure by automating SSH key deployment and sudo configuration.

Deploying SSH Authorized Keys

The ansible.posix.authorized_keyA module for managing SSH authorized keys in users' ~/.ssh/authorized_keys files. module manages SSH authorized keys:

Adding SSH keys
- name: Add SSH key for developer
  ansible.posix.authorized_key:
    user: devuser
    key: "{{ lookup('file', 'files/devuser.pub') }}"
    state: present

- name: Manage exclusive key access
  ansible.posix.authorized_key:
    user: admin
    key: "{{ admin_public_key }}"
    exclusive: true

Configuring Sudo Access

Managing sudo access
- name: Allow developers sudo without password
  ansible.builtin.copy:
    dest: /etc/sudoers.d/developers
    content: "%developers ALL=(ALL) NOPASSWD: ALL\n"
    owner: root
    group: root
    mode: '0440'
    validate: '/usr/sbin/visudo -cf %s'
💡 Best Practice

Always use the validate parameter with visudo when modifying sudoers files to prevent lockouts from syntax errors.

Scheduling with Cron and At

Automate task scheduling across your infrastructure using Ansible's cron and at modules.

The Cron Module

The ansible.builtin.cronA module for managing crontab entries. Create, modify, or remove cron jobs. module manages cron jobs:

Creating cron jobs
- name: Schedule daily backup at 2 AM
  ansible.builtin.cron:
    name: "Daily backup"
    minute: "0"
    hour: "2"
    job: "/usr/local/bin/backup.sh"
    user: root

- name: Run at system reboot
  ansible.builtin.cron:
    name: "Startup script"
    special_time: reboot
    job: "/usr/local/bin/startup.sh"

- name: Every 15 minutes
  ansible.builtin.cron:
    name: "Check health"
    minute: "*/15"
    job: "/usr/local/bin/health.sh"

Cron Time Specifications

ParameterValuesDescription
minute0-59, *, */nMinute of hour
hour0-23, *, */nHour of day
day1-31, *, */nDay of month
month1-12, *, */nMonth of year
weekday0-6 (Sun-Sat)Day of week
special_timereboot, hourly, daily, weekly, monthlyShortcuts

The At Module

The ansible.posix.atA module for scheduling one-time tasks using the at daemon. module schedules one-time tasks:

One-time scheduled tasks
- name: Schedule maintenance in 2 hours
  ansible.posix.at:
    command: "/usr/local/bin/maintenance.sh"
    count: 2
    units: hours
    unique: true

Service Management

Control system services across your infrastructure with Ansible.

The Service Module

The ansible.builtin.serviceA generic service module that works with multiple init systems including systemd, SysV init, and others. module manages services:

Managing services
- name: Start and enable Apache
  ansible.builtin.service:
    name: httpd
    state: started
    enabled: true

- name: Restart service
  ansible.builtin.service:
    name: nginx
    state: restarted

Service States

StateDescription
startedEnsure service is running
stoppedEnsure service is not running
restartedAlways restart the service
reloadedReload configuration

The Systemd Module

Systemd-specific management
- name: Reload systemd daemon
  ansible.builtin.systemd:
    daemon_reload: true

- name: Start custom service
  ansible.builtin.systemd:
    name: myapp
    state: started
    enabled: true
    daemon_reload: true
💡 Best Practice

Use handlers to restart services only when configuration changes:

Using handlers
tasks:
  - name: Deploy configuration
    ansible.builtin.template:
      src: httpd.conf.j2
      dest: /etc/httpd/conf/httpd.conf
    notify: restart apache

handlers:
  - name: restart apache
    ansible.builtin.service:
      name: httpd
      state: restarted

Software Package Management

Maintain consistent software installations across your infrastructure.

The DNF Module

The ansible.builtin.dnfThe package manager module for RHEL 8+, Fedora, and CentOS Stream. module manages packages:

Installing packages
- name: Install multiple packages
  ansible.builtin.dnf:
    name:
      - httpd
      - php
      - mariadb-server
    state: present

- name: Update all packages
  ansible.builtin.dnf:
    name: "*"
    state: latest

- name: Install package group
  ansible.builtin.dnf:
    name: "@Development Tools"
    state: present

- name: Remove package
  ansible.builtin.dnf:
    name: telnet
    state: absent

Package States

StateDescription
presentEnsure package is installed
latestEnsure latest version
absentEnsure package is removed

Managing Repositories

Adding a repository
- name: Add EPEL repository
  ansible.builtin.yum_repository:
    name: epel
    description: "Extra Packages for Enterprise Linux"
    baseurl: "https://dl.fedoraproject.org/pub/epel/$releasever/$basearch/"
    gpgcheck: true
    gpgkey: "https://dl.fedoraproject.org/pub/epel/RPM-GPG-KEY-EPEL-$releasever"
    enabled: true

Storage Configuration

Automate storage provisioning using Ansible and RHEL System Roles.

The Storage System Role

The redhat.rhel_system_roles.storageA Red Hat certified system role for complete storage management including LVM, partitions, and file systems. provides comprehensive storage management:

Using storage system role
---
- name: Configure storage
  hosts: servers
  become: true
  vars:
    storage_pools:
      - name: data_vg
        type: lvm
        disks:
          - /dev/sdb
        volumes:
          - name: app_data
            size: "50 GiB"
            fs_type: xfs
            mount_point: /var/app/data
  roles:
    - redhat.rhel_system_roles.storage

Manual LVM Management

LVM modules
- name: Create volume group
  community.general.lvg:
    vg: data_vg
    pvs: /dev/sdb1

- name: Create logical volume
  community.general.lvol:
    vg: data_vg
    lv: app_data
    size: 50G

- name: Create file system
  community.general.filesystem:
    fstype: xfs
    dev: /dev/data_vg/app_data

- name: Mount file system
  ansible.posix.mount:
    path: /var/app/data
    src: /dev/data_vg/app_data
    fstype: xfs
    state: mounted

Firewall Management

Secure your systems by automating firewall configuration with Ansible.

The Firewalld Module

The ansible.posix.firewalldA module for managing firewalld zones, services, ports, and rich rules. module configures firewall rules:

Firewall configuration
- name: Ensure firewalld is running
  ansible.builtin.service:
    name: firewalld
    state: started
    enabled: true

- name: Allow HTTP service
  ansible.posix.firewalld:
    service: http
    permanent: true
    immediate: true
    state: enabled

- name: Allow custom port
  ansible.posix.firewalld:
    port: 8080/tcp
    permanent: true
    immediate: true
    state: enabled

- name: Add source to trusted zone
  ansible.posix.firewalld:
    zone: trusted
    source: 192.168.1.0/24
    permanent: true
    immediate: true
    state: enabled

Key Firewalld Parameters

ParameterDescription
serviceFirewalld service name (http, ssh, etc.)
portPort/protocol (e.g., 8080/tcp)
zoneFirewalld zone
permanentMake change persistent
immediateApply change immediately
💡 Best Practice

Always set both permanent: true and immediate: true to ensure changes persist across reboots and take effect immediately.

Lab Exercise Automating Server Provisioning

Create a playbook that provisions a new web server with users, packages, services, and firewall rules.

Requirements

  • Create developer user accounts with SSH keys
  • Install and configure Apache web server
  • Configure firewall to allow HTTP/HTTPS
  • Set up scheduled backup job
1
Create project structure 
mkdir -p ~/server-provisioning/{files,vars}
cd ~/server-provisioning
2
Create vars/users.yml 
developers:
  - username: alice
    uid: 2001
    groups: developers,wheel
  - username: bob
    uid: 2002
    groups: developers
3
Create main playbook provision.yml 
---
- name: Provision web server
  hosts: webservers
  become: true
  vars_files:
    - vars/users.yml

  tasks:
    - name: Create developers group
      ansible.builtin.group:
        name: developers
        gid: 2000

    - name: Create developer accounts
      ansible.builtin.user:
        name: "{{ item.username }}"
        uid: "{{ item.uid }}"
        groups: "{{ item.groups }}"
      loop: "{{ developers }}"

    - name: Install web packages
      ansible.builtin.dnf:
        name:
          - httpd
          - mod_ssl
        state: present

    - name: Start Apache
      ansible.builtin.service:
        name: httpd
        state: started
        enabled: true

    - name: Configure firewall
      ansible.posix.firewalld:
        service: "{{ item }}"
        permanent: true
        immediate: true
        state: enabled
      loop:
        - http
        - https

    - name: Schedule daily backup
      ansible.builtin.cron:
        name: "Daily backup"
        minute: "0"
        hour: "2"
        job: "/usr/local/bin/backup.sh"
4
Run the playbook 
ansible-navigator run provision.yml -m stdout
